# Schema-Pack Conformance Data

This directory owns the shared synthetic corpus for schema-pack composition. The base project is intentionally independent of the LoTM pack catalog so both runtimes validate the contract rather than merely accepting current project data.

- `base/` provides a valid schema-5 three-pack composition with independent compatibility kind and architectural classification, foundation/domain/bridge roles, domain scope, rich localizable presentation, dependency ordering, capability lifecycle and activation, multiple providers with equivalent capability presentation, a capability-free vocabulary bridge, cross-pack controlled-value hierarchy, typed occurrence semantic declarations, one used four-dimension state profile plus kind mapping, and one dormant reusable profile.
- `expectations.json` defines exact positive assertions, 91 structured malformed mutations, and the common scale size used by both runners. Presentation cases reject malformed classification, mixed schema versions, incomplete bridges, incompatible dependency scope, localization collisions, missing human metadata, unsafe documentation targets, invalid visual identifiers, string shorthand, and conflicting provider text. Existing state-profile cases retain unsupported-dimension, unusable-availability, and missing/unknown mapping rejection. The paired suites also prove presentation-only edits leave semantic composition unchanged and delimiter-colliding stable IDs remain distinct typed records.
- The generated 64-pack scale corpus uses schema 5 throughout and gives every pack and capability rich presentation metadata. The canonical LoTM catalog remains a supported schema-4 compatibility input until Phase 3.1.3 performs its reviewed all-pack backfill; mixed schema-4/schema-5 compositions fail closed.

The runners copy `base/` into an isolated operating-system temporary directory before applying each mutation. Repository fixtures are never modified, and temporary data is removed after every run.
