# Occurrence Conformance Data

This directory contains the portable V31-V43 occurrence, branch-lifecycle, participation, recurrence, cardinality, policy, and subject-state fixture corpus.

- `valid-registry.yaml` exercises append-only branch-state history, branch continuity membership, fork and merge triggers, both role-distinct and semantically identical ordered participations by one subject in one concrete occurrence, stable track-entry ordering, distinct chronology-context references, exact, minimum, maximum, ranged, unknown, complete, representative, unmaterialized, exact-zero, and signed-64-bit cardinality claims alongside repeated world-time coordinates, coherent multi-axis bindings, recurrence policy, profiled epistemic and non-epistemic state acquisition, carryover, and permitted causal cycles.
- `expectations.json` contributes deterministic cross-runtime query and evaluation results, including branch history and branch-local boundary lookup, participation and entry lookup, explicit occurrence-relative ambiguity rejection, cardinalities ordered by stable ID, exact epistemic state-dimension snapshots, partial-to-complete progression, belief revision, explainable indeterminate evaluation, controlled civil-range failures, conflict traces, and contributor lineage.
- `invalid-cases.json` defines 125 mutations that every runtime must reject, including malformed branch lifecycle, required fork and merge triggers, continuity, participation, target, value, track-entry ownership or order, ambiguous occurrence-level transition/state consumers, malformed cardinality bounds, coverage/list combinations, cross-recurrence representatives, numeric overflow, profile-forbidden or required dimensions, broken completeness chains, unknown change shapes, and the earlier occurrence, policy, state, and lifecycle failures.

The paired conformance tools report 111 query/evaluation assertions and add generated 128-record branch-state, cardinality, and participation/track-entry probes. The positive state corpus consumes `epistemic-access`, `epistemic-belief`, and `availability-state` profiles and validates every controlled dimension rather than testing profile declarations only through pack counts. The positive branch history consumes narrative pruning plus core transfer, restoration, and merge vocabulary. The tools also introduce synthetic typed owning-pattern and external-pattern effects, global and same-target incompatibility, idempotent, accumulating, and invalid repetition, contributor diagnostics, and conflict-wide authorization blocking through pack declarations alone.

The fixture uses the chronology positions in `Framework/Data/Chronology/valid-registry.yaml` and a synthetic `character:protagonist` subject. It is framework conformance data, not LoTM canon.
