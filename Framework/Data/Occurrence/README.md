# Occurrence Conformance Data

This directory contains the portable V31-V46 occurrence, branch-lifecycle, participation, participant-relative chronology, recurrence, cardinality, policy, and subject-state fixture corpus.

- `valid-registry.yaml` exercises append-only branch-state history, branch continuity membership, fork and merge triggers, both role-distinct and semantically identical ordered participations by one subject in one concrete occurrence, stable track-entry ordering, participation- and entry-relative selection across world, personal, control, and presentation axes, exact repeated-visit state activation, exact, minimum, maximum, ranged, unknown, complete, representative, unmaterialized, exact-zero, and signed-64-bit cardinality claims alongside repeated world-time coordinates, coherent multi-axis bindings, recurrence policy, profiled epistemic, capability, credential, and non-epistemic state acquisition, carryover, and permitted causal cycles.
- `expectations.json` contributes deterministic cross-runtime query and evaluation results, including branch history and branch-local boundary lookup, participation, chronology-selection, entry, and exact entry-relative state lookup, explicit occurrence-relative ambiguity rejection, cardinalities ordered by stable ID, exact epistemic state-dimension snapshots, partial-to-complete progression, belief revision, explainable indeterminate evaluation, controlled civil-range failures, conflict traces, and contributor lineage.
- `invalid-cases.json` defines 160 mutations that every runtime must reject, including legacy singular participation contexts; unknown, cross-occurrence, mismatched-context, duplicate, or redundantly inherited chronology links; malformed branch lifecycle; required fork and merge triggers; continuity; participation; target; value; track-entry ownership or order; ambiguous occurrence-level transition/state consumers; malformed activation entries; malformed cardinality bounds; coverage/list combinations; cross-recurrence representatives; numeric overflow; malformed capability scales and values; wrong-direction progression; credential/capability leakage; broken state chains; profile-forbidden or required dimensions; unknown change shapes; and the earlier occurrence, policy, state, and lifecycle failures.

The paired conformance tools report 139 query/evaluation assertions and add generated 128-record branch-state, cardinality, participation/track-entry, and participation-chronology-link probes. The positive state corpus consumes `epistemic-access`, `epistemic-belief`, `capability-state`, and `availability-state` profiles; exercises qualitative and bounded-integer scales; and validates acquisition, practice, retention, carryover, improvement, degradation, loss, restoration, external transfer, bounded assessment evidence, credential separation, and two state changes at separate entries for one repeated occurrence rather than testing profile declarations only through pack counts. The positive branch history consumes narrative pruning plus core transfer, restoration, and merge vocabulary. The tools also introduce synthetic typed owning-pattern and external-pattern effects, global and same-target incompatibility, idempotent, accumulating, and invalid repetition, contributor diagnostics, and conflict-wide authorization blocking through pack declarations alone.

The fixture uses the chronology positions in `Framework/Data/Chronology/valid-registry.yaml` and a synthetic `character:protagonist` subject. It is framework conformance data, not LoTM canon.
